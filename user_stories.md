### **Final Alur Fitur Sertifikasi Kompetensi (Umum dan Teknis)**

**I. Alur Umum (User Flow)**

1. **Perusahaan / LSP / Admin (Pembuat Ujian):**  
   * Membuat dan mengelola daftar ujian sertifikasi (judul, deskripsi, kompetensi terkait, dll.).  
   * Menambahkan dan mengelola soal-soal untuk setiap ujian.  
   * Menginput nilai hasil ujian siswa (setelah siswa mengerjakan).  
   * Menyerahkan/mengunggah sertifikat kelulusan kepada siswa yang lulus (opsional, manual).  
2. **Siswa (Peserta Ujian):**  
   * Melihat daftar ujian sertifikasi yang tersedia.  
   * Memilih ujian dan mendaftar dengan mengunggah dokumen persyaratan.  
   * Setelah mendaftar, langsung dapat mengakses dan mengerjakan ujian.  
   * Melihat nilai atau hasil ujian setelah selesai.  
   * Mengunduh sertifikat jika sudah diberikan oleh Perusahaan/LSP.

**II. Alur Teknis (Data Flow & Modifikasi Database)**

Melihat struktur database yang ada (`sertifikasis`, `kuis_lsps`, `soal_lsps`), dan berdasarkan alur final di atas, berikut adalah modifikasi dan relasi yang diperlukan:

**A. Modifikasi dan Penambahan Struktur Tabel:**

1. **Tabel `users`:**  
   * Tidak ada perubahan signifikan yang diperlukan untuk fitur ini, karena `users.id` akan digunakan sebagai *foreign key*.  
2. **Tabel `sertifikasis`:**  
   * **Perubahan `nama_siswa`:** Ubah tipe data `varchar(255)` menjadi `bigint(20) UNSIGNED NOT NULL` dan jadikan `user_id` (FK ke `users.id`). Ini jauh lebih baik untuk relasi dan integritas data.  
   * **Perubahan `nama_lsp`:** Ubah tipe data `varchar(255)` menjadi `bigint(20) UNSIGNED NULL` (bisa `NULL` jika dibuat oleh perusahaan) dan jadikan `lsp_user_id` (FK ke `users.id` dengan role `lsp`).  
   * **Penambahan `perusahaan_user_id`:** Tambahkan kolom `bigint(20) UNSIGNED NULL` sebagai FK ke `users.id` dengan role `perusahaan`. Ini untuk menandai perusahaan mana yang membuat ujian/sertifikasi ini.  
   * **Penambahan `certification_exam_id`:** Tambahkan kolom `bigint(20) UNSIGNED NOT NULL` sebagai FK ke tabel `certification_exams` yang baru (lihat poin B). Ini akan menghubungkan pendaftaran siswa ke set ujian tertentu.  
   * **Penambahan `status_pendaftaran_ujian`:** Tambahkan kolom `enum('terdaftar', 'selesai_ujian', 'lulus', 'tidak_lulus') NOT NULL DEFAULT 'terdaftar'`. Ini akan melacak progres siswa.  
   * Kolom `nilai` dan `sertifikat_kelulusan` sudah ada, dan akan digunakan untuk menyimpan nilai akhir ujian dan path file sertifikat yang diunggah secara manual.  
   * Kolom `kompetensi`, `dokumen_persyaratan` sudah ada.  
3. **Tabel `kuis_lsps`:**  
   * **Ganti Nama Tabel:** Ganti nama tabel ini menjadi `student_exam_attempts` atau `ujian_sertifikasi_attempts` (upaya ujian siswa).  
   * **Relasi ke Ujian Master:** Ubah `id_user` menjadi `user_id` (FK ke `users.id`) dan tambahkan `certification_exam_id` (FK ke `certification_exams.id`).  
   * **`nilai`:** Kolom `nilai` akan menyimpan nilai dari upaya kuis tersebut.  
   * Kolom `created_at` dan `updated_at` sudah ada.  
   * Setiap kali siswa memulai ujian, sebuah entri baru dibuat di sini. Jika siswa bisa mengulang, akan ada beberapa entri per siswa per ujian.  
4. **Tabel `soal_lsps`:**  
   * **Ganti Nama Tabel:** Ganti nama tabel ini menjadi `certification_exam_questions` atau `soal_ujian_sertifikasi`.  
   * **Relasi ke Ujian Master:** Ubah `kuis_id` menjadi `certification_exam_id` (FK ke tabel `certification_exams` yang baru).  
   * Kolom `soal`, `pilihan_jawaban_1` sampai `4`, `jawaban_benar`, `nilai_akhir` (ini bobot per soal) sudah relevan.

**B. Penambahan Tabel Baru: `certification_exams` (atau `ujian_sertifikasis`)**

Tabel ini akan bertindak sebagai "Master Ujian" yang bisa dibuat oleh LSP atau Perusahaan.

SQL  
CREATE TABLE \`certification\_exams\` (  
  \`id\` bigint(20) UNSIGNED NOT NULL AUTO\_INCREMENT,  
  \`nama\_ujian\` varchar(255) NOT NULL,  
  \`deskripsi\` text DEFAULT NULL,  
  \`kompetensi\_terkait\` varchar(255) DEFAULT NULL, \-- Opsional, bisa string atau FK ke tabel kompetensi jika ada  
  \`pembuat\_user\_id\` bigint(20) UNSIGNED NOT NULL, \-- FK ke users.id (bisa LSP atau Perusahaan)  
  \`durasi\_menit\` int(11) DEFAULT NULL, \-- Durasi ujian dalam menit  
  \`nilai\_minimum\_lulus\` int(11) NOT NULL, \-- Nilai minimal untuk lulus  
  \`status\_ujian\` enum('draft', 'published', 'archived') NOT NULL DEFAULT 'draft',  
  \`created\_at\` timestamp NULL DEFAULT NULL,  
  \`updated\_at\` timestamp NULL DEFAULT NULL,  
  PRIMARY KEY (\`id\`),  
  CONSTRAINT \`fk\_pembuat\_user\` FOREIGN KEY (\`pembuat\_user\_id\`) REFERENCES \`users\` (\`id\`) ON DELETE CASCADE  
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4\_unicode\_ci;

**C. Relasi Antar Tabel:**

* `users` (id) \-- FK \--\> `certification_exams` (pembuat\_user\_id)  
* `certification_exams` (id) \-- FK \--\> `sertifikasis` (certification\_exam\_id)

**D. Alur Teknis Rinci (Setelah Perubahan DB):**

1. **Pembuatan Ujian (Perusahaan/LSP/Admin):**  
   * Perusahaan/LSP/Admin membuat entri di tabel `certification_exams` (`nama_ujian`, `deskripsi`, `pembuat_user_id`, `nilai_minimum_lulus`, dll.).  
   * Mereka kemudian menambahkan soal-soal untuk ujian tersebut ke tabel `soal_lsps` (`soal`, `pilihan_jawaban`, `jawaban_benar`, `certification_exam_id`).  
   * Mengatur `status_ujian` di `certification_exams` menjadi `published` agar bisa diakses siswa.  
2. **Pendaftaran Ujian (Siswa):**  
   * Siswa melihat daftar `certification_exams` yang `published`.  
   * Siswa mendaftar dengan membuat entri di tabel `sertifikasis`.  
     * `user_id`: ID siswa.  
     * `certification_exam_id`: ID ujian yang dipilih.  
     * `dokumen_persyaratan`: Path file yang diunggah.  
     * `status_pendaftaran_ujian`: Otomatis `terdaftar`.  
     * `created_at`, `updated_at`.  
3. **Mengerjakan Ujian (Siswa):**  
   * Setelah mendaftar, siswa bisa langsung mengakses halaman ujian.  
   * Sistem akan mengambil soal-soal dari `soal_lsps` berdasarkan `certification_exam_id`.  
   * Saat siswa mengerjakan dan menyelesaikan ujian:  
     * Hasil ujian (misal, jawaban siswa, waktu mulai/selesai) dapat disimpan sementara atau langsung diproses.  
     * Setelah submit, sistem menghitung `nilai` dan membuat entri di `kuis_lsps` (`user_id`, `certification_exam_id`, `nilai`).  
     * Status siswa di `sertifikasis` diperbarui menjadi `selesai_ujian`.  
4. **Peninjauan & Penilaian (Perusahaan/LSP/Admin):**  
   * Perusahaan/LSP/Admin dapat melihat daftar siswa yang telah `selesai_ujian` dari tabel `sertifikasis`.  
   * Mereka dapat melihat detail `nilai` dari tabel `kuis_lsps`.  
   * Secara manual, Perusahaan/LSP/Admin dapat mengubah `status_pendaftaran_ujian` di tabel `sertifikasis` menjadi `lulus` atau `tidak_lulus` berdasarkan `nilai` dan `nilai_minimum_lulus` dari `certification_exams`.  
   * Jika `lulus`, Perusahaan/LSP/Admin dapat mengunggah file sertifikat ke kolom `sertifikat_kelulusan` di tabel `sertifikasis`.  
5. **Melihat Hasil & Sertifikat (Siswa):**  
   * Siswa dapat melihat `status_pendaftaran_ujian` mereka di `sertifikasis`.  
   * Jika `lulus` dan `sertifikat_kelulusan` tidak kosong, siswa dapat mengunduh sertifikatnya.
